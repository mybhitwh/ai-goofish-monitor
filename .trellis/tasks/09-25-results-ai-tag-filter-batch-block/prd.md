# 结果页 AI 标签筛选与批量屏蔽

## Goal

结果页缺少「按 AI 判定原因筛选 + 批量屏蔽」：AI 已在 `risk_tags` 输出型号不符 / 容量不符 / 卖家信用不足 等标签（线上 273/274 条非空），但只存在 `raw_json` 里，没有可筛选字段、没有展示；屏蔽只能逐条点，理由也落不回细粒度标签（线上 157 条已屏蔽中有 84 条统一打了「不符合我的要求」）。

本任务要达成三件事：

- 商品卡片上直接显示 AI 给出的不符合原因标签，而不是让人读一整句 `reason`。
- 这些标签可以在筛选条里按需勾选，与既有筛选（推荐状态、用户标签、是否含已屏蔽）自由组合。
- 对筛选出的整批结果**一键批量屏蔽**（并可选批量恢复），批量动作作用于**全部匹配行**、不是当前页的前 100 条；屏蔽理由按既有契约落成用户标签，便于事后审计。

用户价值：现在"整理"结果页只有一条路——逐条点屏蔽，且理由只能手打；线上 157 条已屏蔽商品里 84 条只打了同一个笼统标签，而 AI 其实早就逐条给出了细粒度原因，只是这份判断从来没有进入筛选与批量操作的路径。

## Background（已核实事实）

详细代码地图与线上分布见 `research/ai-tags-and-results-filter-map.md`（含只读复现脚本与全部 file:line 锚点）。

- **AI 已经在打标签，但它只活在 `raw_json` 里。** `prompts/base_prompt.txt:10-46` 的输出格式包含 `risk_tags: ["string"]`，线上 273/274 条非空。但 `result_items`（`src/infrastructure/persistence/sqlite_connection.py:51-72`）没有标签列，`src/api/routes/results.py` 没有任何按标签筛选的参数，前端只声明了类型（`web-ui/src/types/result.d.ts:45-46`）而没有任何组件渲染它。
- **词表已经漂移，直接拿来做筛选会碎成一堆近义标签。** `active` 117 条上的实际取值：`卖家信用缺失`(24) / `卖家信用不足`(19) / `卖家信用差`(4) 是同一件事；`信息缺失`(38) / `信息不透明`(4) / `需确认维修史`(4) / `未验证身份`(3) / `NEEDS_MANUAL_CHECK`(3) 是一族；`商家贩子`(18) / `批量同型号`(4) / `同型号密集出货`(4) 也是一族；而 `有条件推荐`(36) 根本不是"不符原因"。校验器只检查 `risk_tags` 是 list（`src/ai_handler.py:240-276`），没有枚举约束。
- **典型场景的真实规模**：`active` 117 条中 `is_recommended=false` 的有 74 条，分布在 4 个结果文件（`iPad_Air_M4` 21 / `iPad_Air_11_256` 21 / `iPad_Air_8` 22 / `iPad_Air` 10）。这正是"筛选后批量屏蔽"要处理的量级。
- **读路径天然适合派生标签**：列表查询 `_load_filtered_records_from_conn`（`src/services/result_storage_service.py:115-161`）已经一次性读取该文件全部行并**逐行 `json.loads(raw_json)`**，再在 Python 里完成 hidden / 黑名单 / 用户标签 / note 过滤与分页切片。因此 `_ai_tags` 可以在读路径派生：**不需要 DDL、迁移或回填，存量 274 行立即生效**。加物理列的代价相反：写入是 `INSERT OR IGNORE`（`:168-209`），存量行永远不会被更新，必须回填，而回填只能拿到老字段。
- **`criteria_analysis.*.status` 不能作为确定性派生源**：线上同时存在 `FAIL`/`fail`、`pass`/`PASS`、`NEEDS_MANUAL_CHECK`/`needs_manual_check` 以及 `ACCEPTABLE`/`GOOD`/`WARNING`/`PERSONAL_PLAYER`/`PARTIAL_DEFECT` 等词表外值。`risk_tags` 才是稳定且持续被填写的字段。
- **批量屏蔽没有替代路径，且逐条屏蔽的代价会外溢到复查**：现有 API 只有单条 `PATCH .../items/{item_id}/status`（`src/api/routes/results.py:205-229`）；前端 `blockItem`（`web-ui/src/composables/useResults.ts:441-455`）每屏蔽一条都要整表刷新。而 hidden 会被排除出列表 / insights / 导出 / 概览，**并且只有 `status='active'` 会被复查**（`src/services/item_recheck_service.py:51-79`）、`load_processed_link_keys` 返回所有 status（`result_storage_service.py:212-220`），即被屏蔽的商品不再抓详情——所以批量屏蔽既是效率功能，也必须带上明确的确认与恢复路径。
- **可见集合只有每文件前 100 条**：前端固定 `page=1, limit=100`（`useResults.ts:40-41`），后端 `limit` 上限也是 100（`results.py:98-99`），而 `GET /{filename}` 的 `total_items` 是**过滤后、切片前**的真实计数。批量操作必须由服务端按筛选条件选目标，确认弹窗要能说明"其中 N 条未在当前页显示"。
- **屏蔽理由的既有持久化契约是用户标签**：`blockItem` 先把理由并进 `_user_tags`（`item_annotation_service.update_annotation_sync`，全局按 `link_unique_key` 存于 `item_annotations`），再改 status。批量屏蔽沿用同一契约，不新造理由字段。

### R2 (P0) 标签在读路径派生为 `_ai_tags`，存量数据立即生效

- 每条结果记录的标签派生规则：优先取 `raw_json.ai_analysis.risk_tags` 并归一化；`risk_tags` 为空且 `is_recommended=false` 时，回退用 `criteria_analysis` 的失败项（大小写不敏感匹配）映射到词表；仍为空则给兜底标签 `其他不符要求`。
- **分析失败记录必须被排除**：带 `ai_analysis.error` 的记录（`AI分析异常` 形态，见 `src/services/item_analysis_dispatcher.py:112-142`）不打任何"不符原因"标签——它是基础设施故障，不是判定结果。该规则要能随 `09-25-fix-ai-moderation-rejected-analysis` 引入的失败态标记同步演进，不得把失败吞成「其他不符要求」。
- 派生结果通过既有装饰通道随 item 一起下发（与 `_status`、`_user_tags`、`_hidden_reason` 同级），前端无需二次解析 `raw_json`。
- 不新增数据库列、不做迁移、不回填；实现后对线上现有 274 行立即生效（可离线只读验证）。

### R3 (P0) 按 AI 标签筛选（列表 / insights / 导出 一致）

- 结果列表新增标签筛选参数，逗号分隔、多标签取 **OR**（与既有用户标签筛选 `tags=` 语义一致），可与 `ai_recommended_only` / `keyword_recommended_only` / `tags=` / `has_note` / `include_hidden` 任意组合。
- 新增标签 facets 端点，返回 `{name, count}`，用于筛选条渲染可点的标签与计数；支持按结果文件限定范围，并可选是否计入已屏蔽项（默认与列表一致：不计入）。
- `insights` 与 CSV `export` 必须与列表使用同一套筛选口径（含新增参数），否则导出的 CSV 与页面看到的集合不一致。
- v1 的 facets 计数是**该范围内可见集合的静态计数**，不随其它已激活筛选联动（已知限制，见 Non-goals）。

### R4 (P0) 按筛选条件批量改状态（屏蔽 / 恢复）

- 新增服务端批量端点：以**筛选条件**选中目标（不是前端已加载的 100 条），对全部匹配行改 status，返回真实 `affected` 计数。
- 安全护栏（缺一不可）：
  - 必须具备至少一个收窄条件（AI 标签 / 用户标签 / 推荐状态 / has_note），否则拒绝执行（400）——不允许"无筛选地屏蔽整个文件"。
  - 屏蔽只作用于 `status='active'`，恢复只作用于 `status='hidden'`；`expired` 在任何情况下都不被触碰。
  - 支持 `dry_run`：只返回将要影响的行数、不写库，供确认弹窗取数与批量写库共用同一套判定，避免"弹窗说 74 条、实际动了别的条数"。
- 批量屏蔽可携带理由标签，按既有契约**合并**进 `_user_tags`（去重、trim、非空校验、数量与长度上限），默认值由前端用当前选中的 AI 标签预填、用户可编辑或清空。
- 合并视图（`__all__` / `__group_{id}__`）下由前端对成员文件逐个调用并汇总 `affected`，每个文件只动自己的行；任一文件失败要如实报告部分失败，不能报成全部成功。

### R5 (P0) 前端：卡片标签、标签筛选、批量操作

- `ResultCard` 展示 AI 标签：与用户标签在视觉上可区分（例如不同变体 / 前缀标识），只读，不混进用户标签编辑面板。
- `ResultsFilterBar` 新增「AI 标签」facet 区：显示标签与计数、多选切换、已选项高亮；无标签时不渲染该区域。
- 批量动作按钮与确认弹窗：按钮文案带当前匹配计数（如「批量屏蔽（74）」）；`include_hidden=false` 时是屏蔽、勾选"包含已屏蔽"后是恢复；无收窄条件或计数为 0 时禁用。弹窗必须显示：将影响的条数、其中多少条未在当前页显示、屏蔽的连带后果（不再参与复查与详情抓取）、理由标签输入（默认填当前选中的 AI 标签，可编辑 / 清空）。
- 执行成功后刷新列表与 facets，并给出「已屏蔽 N 条 / 已恢复 N 条」的可见反馈；失败要给可读错误（含部分失败计数）。
- 文案同时补 `zh-CN` 与 `en-US`，键位结构保持一致。

### R6 (P1) 点击卡片上的标签即加入筛选

卡片上的 AI 标签可点击，点击后该标签加入筛选条件（等价于在筛选条勾选它），便于"看到一个典型样本 → 立刻按同类筛选"的工作流。

### R7 (P0) 测试与基线

- 新增单元测试：词表归一化（映射表、去重、上限、未知标签保留、`有条件推荐` 丢弃）、派生回退链（`risk_tags` → `criteria_analysis` 失败项 → 兜底）、`error` 记录被排除。
- 新增集成测试：`_ai_tags` 装饰、标签筛选（单标签 / 多标签 OR / 与其它条件组合）、facets 计数与范围、batch 端点的护栏（无收窄条件 400、`expired` 不动、屏蔽只动 active、恢复只动 hidden）、理由标签合并进 `_user_tags`、多文件隔离。
- 测试不得触碰仓库 `data/app.sqlite3`（沿用 `monkeypatch.chdir(tmp_path)` + legacy `jsonl` bootstrap 的既有隔离方式）。
- 全量测试不得引入新的失败（u12 基线：130 passed / 3 failed / 3 skipped）；`web-ui` 改动后必须 `pnpm build` 且 `dist/` 与源码一致（`tests/test_frontend_build_paths.py` 必须保持通过）。

## Non-goals（明确不做）

- **逐条勾选多选**：批量目标由筛选条件定义，不引入卡片复选框。
- **分页 UI**：仍只展示前 100 条；批量操作由服务端覆盖全部匹配行，页面用确认弹窗说明未显示条数。
- **其它筛选维度**（价格区间、卖家、发布时间等）不在本任务范围。
- **对存量商品重新分析以刷新标签**：不新增抓取与 AI 调用；存量行用回退链得到粗粒度标签（细粒度标签从下一次分析开始产生）。
- **facets 联动计数**（在当前其它筛选条件下计算每个标签计数）留待后续。
- **改变通知行为**：屏蔽不影响已发出的通知（通知在分析时触发，与 status 无关）。

## Acceptance Criteria

- [ ] 基础提示词含固定词表与规则，文件仍为 CRLF；本任务之外无其它字段契约变更（`is_recommended` / `reason` / `criteria_analysis` 不变）。
- [ ] `GET /api/results/{filename}` 的每条 item 带 `_ai_tags`；对线上 274 行离线只读跑派生：`risk_tags` 非空的记录归一化后非空，14 词条计数等于把原始变体合并后的计数（2026-09-26 真值：型号不符 167、容量不符 102、卖家信用低 96、信息缺失 74、商家或贩子 58、交易方式不符 17、描述与实际不符 13、电池健康未知 10、拆修或维修史 10、版本不符 9、其他不符要求 7、成色问题 5、疑似低价钓鱼 1；裸未知标签 0 个；可复算）。
- [ ] `?ai_tags=型号不符` 返回的每条都含该标签；`?ai_tags=型号不符,容量不符` 为 OR；与 `has_note` / `tags=` / `include_hidden` 组合行为符合定义。
- [ ] facets 端点的计数与该范围可见集合中的标签出现次数一致；`filename` 限定与全局两种调用都正确；`include_hidden=true` 时包含已屏蔽项。
- [ ] 批量屏蔽：`affected` 等于 dry_run 预览数，等于 `GET` 同条件下的 `total_items`；目标行 status 由 `active` 变 `hidden`，`expired` 行不变；未参与筛选的行不受影响；无收窄条件返回 400。
