# AI 前置标题预筛与跨任务复用：淘汰型号/容量不符商品，省 token 与详情抓取

## Goal

闲鱼搜索是模糊匹配（关键词 iPad Air 8 / iPad Air M4 / iPad Air 都会返回 Air 7、Air 6、M3 机型、128G/512G、13 寸、甚至 iPhone Air），而当前管线在列表解析后、AI 分析前没有任何本地确定性校验：每个新链接都要开一次详情页再发一次全量图片的多模态 AI 请求，不符合条件的商品也照付。2026-09-25 生产数据：最近一轮 4 个任务共分析 274 条，其中 137 条（50%）仅凭标题即可判定不符合「iPad Air 8 / 11 寸 / 256G」硬性标准，AI 仍逐个分析；另 106 条（39%）是同一商品被多个任务重复分析（去重仅按结果文件生效）。本任务做两件事：把「仅凭标题即可判定的一票否决规则」前移为确定性预筛（在开详情页之前短路，省 token 也省抓取与风控暴露），以及按 (商品唯一键 + 提示词指纹) 跨任务复用已完成的判定。

用户价值：同样一轮扫描，AI 调用从 274 次降到约 79 次（−71%），结果页不再被「128G / Air 7 / M3 / 13 寸 / iPhone Air」这类一眼就能排除的卡片占满；顺带修掉当前 2 个把 Air 7 判成推荐的误报。

证据与复现见 `research/title-prefilter-evidence.md`。

## Background

- 运行时链路：搜索页筛选（价格/包邮/个人闲置/地区/发布时间）→ 解析列表 API → 逐商品去重 → **开详情页** → 异步 dispatcher（抓卖家主页 → 下载全量图片 → AI 多模态判定 → 落库 → 命中才通知）。
- `keyword_rules` 目前只是「关键词模式（`decision_mode=keyword`）」的 OR 白名单，在 AI 模式下被完全忽略，因此对 AI token 没有任何拦截作用。
- 三个浪费点，按可省的量级排序：
  1. **AI 之前没有确定性校验**：硬性规则里「容量 / 型号 / 尺寸 / 版本 / 风险机」这几条，很多仅凭标题即可定论，却全部交给多模态模型（含全部全分辨率图片）去判。
  2. **跨任务重复分析**：去重记忆按 `result_filename` 隔离，同一商品被 4 个关键词搜到就分析 4 次（本样本 106 次冗余）。
  3. **每次调用的入参偏重**：全量图片不缩放直传——已由 `09-25-fix-ai-moderation-rejected-analysis` 覆盖，本任务不重复处理（见 Non-goals）。

## Requirements

### R1 (P0) 任务级可配置的标题排除词

- 任务新增一个「标题排除词」配置：一组关键词，命中任意一个即判定该商品不符合任务要求。
- 语义是**纯排除**：不要求标题出现任何「正信号」（M4/Air8/2026 之类）。缺正信号的真实 256G 商品（例如标题只写「iPad Air 11英寸 紫色 WLAN版 256G」）必须照常进入 AI，不得因为缺少型号标记被拦。
- 规则必须是任务级配置，不是写死在代码里的常量；本实例的 iPad 任务可配置：容量（64G/128G/512G/1TB/2TB）、芯片/代次（M1/M2/M3、Air5/6/7、第 5/6/7 代）、尺寸（13 寸/12.9 寸）、机型（iPhone Air、iPad Pro、iPad mini）、版本（港/美/日/韩/欧版、外版、资源机、官换机、展示机、教育版）、风险机（维修/换屏/换电池/进水/监管机/隐藏 ID/扩容机）。
- 未配置排除词的任务行为完全不变（默认空）。
- 配置入口：REST API 与任务表单 UI 都能读写该字段（沿用既有任务字段的读写与校验风格）。

### R2 (P0) 在详情页抓取之前短路，并留下可审计记录

- 预筛判定必须发生在**打开详情页之前**：命中排除词的商品本轮不再新建 page、不抓详情、不做卖家主页采集、不发 AI 请求。
- 每命中一条要能回答「为什么被淘汰」：淘汰记录里带命中的关键词与任务名；日志按轮给出汇总（本轮淘汰 N 条 + 各关键词计数）。
- 淘汰记录写入结果存储（可被结果页/结果文件看到），但**不能占用去重记忆**：规则修正或卖家改标题后，下一次运行必须能重新见到该商品（重新判定仍是零网络开销的标题匹配，不会因此多花钱）。
- 命中判定不得影响价格快照（`price_snapshots` 仍按列表页全量写入，行情样本口径不变）。
- 判定是纯本地字符串运算，不发任何网络请求。

### R3 (P0) 结果页默认不被淘汰项干扰，但可复核

- 结果页默认不展示被预筛淘汰的卡片（它们不该再占用人工复核的注意力）。
- 提供一个开关/筛选，可显式查看被淘汰项及其淘汰关键词，用于事后复核（例如怀疑某条被误杀）。
- 淘汰项不参与「推荐」计数与通知（`is_recommended=0`，永不通知）。

### R4 (P1) 同一商品的判定跨任务复用

- 同一 `link_unique_key` 的商品，如果判定所用的提示词与配置指纹相同（criteria 文件内容 + `analyze_images` + `decision_mode`），后续任务直接复用已有判定，不再重复调用模型。
- 复用必须带护栏：价格相对上次判定变动超过阈值、或距上次判定超过 N 天时，重新分析（价格是「低价钓鱼」判据的输入，形状会变）。
- 复用在结果上要可辨认：卡片/记录能区分「本次新分析」与「复用历史判定」，并保留原判定时间。
- 与 R1 的关系：先预筛（省钱且更快），再复用（省钱），两者独立生效；任一单独上线都应有可测量的收益。

## Decisions（已定，review 可改）

- **只做排除、不做「必须有正信号」**：正信号必需会带来召回风险（真实 256G 标题可能不含 M4/Air8/2026 字样），收益不值这个风险。
- **淘汰项落库但不占去重位**：可审计（R3）与「规则改好能立刻纠偏」二者都要；实现方式见 design.md。
- **不引入新的规则 DSL**：排除词就是一组字符串关键词，复用既有「多行文本 / 数组 → 归一化」的既有写法，不做 include/exclude/price 之类的结构化规则引擎。
- **复用放在落库侧而不是爬虫侧**：复用仍然需要拿到当前商品与价格，因此复用的判定点在 dispatcher，不在列表循环。
- **本任务的验证一律用 `--debug-limit` 的小样本离线/调试跑**：任务组当前因风控事故处于禁用状态（见 `09-25-fix-risk-control-stop-loss`），不得为了验证本任务而启用生产任务组。
- 复用项计入前端「AI 推荐」筛选（2026-09-26 定）：筛选条件改为 analysis_source IN ('ai','ai-reused')；理由与契约见 design.md。

## Non-goals

- 不处理「AI 单次调用入参过重」（图片缩放/转码）——归 `09-25-fix-ai-moderation-rejected-analysis`。
- 不处理风控、串行化、重复调度——归 `09-25-fix-risk-control-stop-loss`。
- 不改判定标准本身的措辞与判据（`prompts/*_criteria.txt` 内容不动），本任务只把其中「仅凭标题即可定论」的部分前移。
- 不做关键词策略调整（例如把 `iPad Air` 收窄）——属用户侧任务配置，不在代码范围。
- 不覆盖 `item_recheck_service` 的复核链路（复核走的是已分析商品的过期重检，不受本任务影响）。
- 不引入第三方依赖。

## Acceptance Criteria

- **AC1 配置链路**：任务可通过 API 与任务表单设置 `title_exclude_keywords`（多行文本，一行一个；数组入参同样接受）；老任务（字段缺省）读出为空数组且行为不变；`data/app.sqlite3` 在已有生产库上原地升级成功（无损、幂等、可重复启动）。
- **AC2 命中即短路**：配置了排除词后，标题命中排除词的商品在本轮**不产生详情页请求**（可用 `logs/` 日志或无头调试跑核对：无对应的「获取详情」行）、不落 `analysis_source` 为 `ai` 的记录、不触发通知。
- **AC3 否定前缀不误杀**：`无拆无修`、`没拆没修`、`无进水`、`无维修`、`全新未拆封` 这类**否定语**不得被判命中；针对该条要有单元测试锁定用例（取自 `research/title-prefilter-evidence.md` 第 5 节的真实标题）。
- **AC4 无正信号不受影响**：标题不含 M4/Air8/2026 但符合任务要求（如「iPad Air 11英寸 紫色 WLAN版 256G，国行，在保」）的商品仍会进入 AI 分析——用真实标题做单元/集成用例锁定。
- **AC5 离线评测零误杀**：用 `result_items` 现有 274 条标题做离线回归，命中排除词 137 条，其中不含真正的 Air 8 / M4 / 256G 国行商品；评测脚本与结论落到 `research/`。
- **AC6 淘汰可审计且不占去重位**：淘汰记录可在结果侧查到（含命中关键词）；同一商品在规则修正后重跑能被重新判定（不被「已处理」跳过）。
- **AC7 结果页默认清爽**：默认视图看不到淘汰项；打开开关后能看到，且能看到淘汰关键词；淘汰项不出现在推荐筛选与通知里。
- **AC8 复用护栏**：同一商品 + 相同指纹时不再调用模型（用假 analyzer 计数断言）；价格超出阈值或超过 TTL 时重新分析；复用记录能区分来源且保留原判定时间。
- **AC9 不回归**：`.venv/bin/python -m pytest tests/ -s` 不劣于基线（130 passed / 3 failed / 3 skipped，3 个失败为存量）；`decision_mode=keyword` 与 `analyze_images=false` 路径行为不变；`cd web-ui && pnpm build` 成功。
- **AC10 收益可量化**：在真实样本上给出「改造前 vs 改造后」的 AI 调用次数对比（预期 274 → 约 79，−71%），以日志/统计口径呈现，而不是只给估算。
